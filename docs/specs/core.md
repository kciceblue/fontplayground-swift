# Core model (FPCore)

> Scope: WP-301, WP-302, WP-303, WP-304, WP-305 · Env: linux · Architecture refs: docs/architecture.md §2 (FPCore row, dependency rule), §4 (steps 3–7), §5 (identity of a face), §8 (atomic writes, no silent drops) · ADRs: 0002, 0005, 0006, 0007, 0008, 0011, 0012

## Context

The original app keeps its whole editable state in `ForgeModel` (`reference/fontplayground-py/fontplayground/ui/model.py:173-868`), a `QObject` that also owns a plan debounce timer, the combine worker and the temporary result file. The decisions it makes are pure functions spread over five modules:

| Original module | What it decides | Ported to |
|---|---|---|
| `engine/scripts.py:16-68` | 15 script groups; `group_of(cp)` via `fontTools.unicodedata.script` | WP-301 `ScriptGroup` + generated table |
| `ui/languages.py:23-196` | languages, "draws it well" thresholds, samples, card wording | WP-301 `Languages`, `Samples`, `EnglishText` |
| `ui/textutil.py:7-23` | which characters count as visible | WP-301 `TextUtil` |
| `engine/planner.py:10-27`, `ui/mix.py:18-43` | which material draws each code point | WP-302 `Planner`, `Mix` |
| `ui/model.py`, `engine/spec.py:16-95` | recipe state, operations, validity, ForgeSpec | WP-303 `Recipe` |
| `ui/smart.py:19-193` | rules, names, glyph budget, suggestions | WP-303 (rules, names, budget), WP-304 (suggestions) |
| `ui/model.py:678-731` + `ui/app.py:97-102` | settings files | WP-305 `RecipeDocument`, `AppSettings`, `LegacyImport` |

`FPCore` is the Foundation-only Swift port of that logic (architecture §2, ADR-0005, ADR-0006). It is verified in two ways: the original tests are ported test by test (Appendix A), and generated conformance fixtures (`spec/fixtures/**`, WP-202) lock the parts where byte-identical answers matter (script groups, `source_of`, languages, visible characters, naming).

The audit adds macOS requirements the original never had:

- Hidden faces and `.LastResort` must never be suggested or take a group (`CATALOG-2`, verifier: "apply the guard in smart_supplier/group_counts as well as suggest_materials").
- AAT-only fonts cannot shape complex scripts after a forge (`ENGINE-2`, ADR-0008). The engine (WP-107, `engine-metadata.md` S4) reports per face the code points it cannot shape (`unshaped`) and plans with **plannable coverage** (`coverage − unshaped`). FPCore must plan, count, suggest and list missing characters with the same plannable coverage (S7), so the preview never shows a character the forged font will not draw, and must flag a rule that assigns a complex group to a face that cannot shape it (the engine's `aat_unsupported_script`).
- Suggestions should prefer the font macOS itself uses for a language (`CATALOG-11`, verifier: tie-breaker, not pin).
- A requested weight should use a real heavier face of the same family before synthetic bold (`ENGINE-4`, verifier).
- Materials must survive path changes (AssetsV2 hash folders) and must never be dropped silently (`ENGINE-8`, `CATALOG-7`, `CRIT-2`).
- Windows recipes and settings must migrate without junk paths, and Windows-only fonts need Mac equivalents (`CRIT-2`, `CRIT-3`).

What is **not** ported into FPCore (Qt or process lifecycle; see the "Not ported" table in WP-303): the 150 ms plan debounce (ADR-0006 drops it), `CombineWorker`, the temporary result folder, `save_to`, `discard_result`, cancel, `STAGE_TEXT`, and all Qt signals.

### S2. Conventions (normative for every WP here)

- `import Foundation` is the only import in `Sources/FPCore` (AGENTS rule 2). The one sanctioned exception is described in WP-305 (`AtomicFile.swift`).
- Every public type is a value type and `Sendable`. There are no classes, actors, timers, threads, notifications or global mutable state (ADR-0006).
- Swift 6 language mode, strict concurrency, Swift Testing (`import Testing`), `swift format` clean.
- **Code points, not Characters.** Python iterates a `str` by code point. Every text operation here iterates `String.unicodeScalars` and sorts by `Unicode.Scalar.value`. Never use `Character` (grapheme clusters) for coverage, missing characters or runs.
- **No user-facing localized strings in FPCore.** Problems, notes and summaries are typed enums and structs. `FPCore.EnglishText` renders them to the original English wording. It is used by `fpctl`, by tests and as the source text of the String Catalog. `FPAppUI` must not show `EnglishText` output. It renders the typed values through `Localizable.xcstrings` (WP-507). The exception is text that comes from the engine as data (`FaceRecord.unsupportedReason`, `ForgeReport.warnings`), which is shown as is.
- **Audit regression tests** are Swift Testing tests whose display name starts with the finding ID and whose function name starts with the ID in lowerCamelCase: `@Test("ENGINE-8: a material whose file moved is found again by PostScript name") func engine8MovedAssetPathIsReresolvedByPostScriptName()`. Comments on the lines that exist because of a finding cite it (`// CATALOG-2: …`).
- Every `mutating` operation that mirrors a `ForgeModel` method returning `bool` returns `Bool` ("something changed") and is `@discardableResult`.
- **Citations.** Short reference citations expand as follows: `model.py`, `smart.py`, `languages.py`, `mix.py`, `textutil.py`, `ui/recipe.py`, `ui/app.py`, `ui/theme.py` → `reference/fontplayground-py/fontplayground/ui/<file>`; `planner.py`, `scripts.py`, `spec.py`, `prepare.py`, `synth_bold.py`, `merge.py` (also written `engine/<file>`) → `reference/fontplayground-py/fontplayground/engine/<file>`; `face.py`, `cache.py` (also `catalog/<file>`) → `reference/fontplayground-py/fontplayground/catalog/<file>`; `paths.py` → `reference/fontplayground-py/fontplayground/paths.py`; `test_*.py`, `fixtures.py`, `conftest.py` → `reference/fontplayground-py/tests/<file>`. A bare `:N-M` repeats the file of the table or paragraph it appears in.

### S7. Plannable coverage and the shaping rule (normative; mirrors `engine-metadata.md` S4 and WP-107 §4–5)

- `FaceRecord.unshaped` is the set of code points the engine says the face covers but cannot shape (WP-107 rules U1/U2). `FaceRecord.plannableCoverage = coverage.subtracting(unshaped)`.
- **Everything in FPCore that decides "which font draws this character" uses `plannableCoverage`**: `MixFont.effectiveCoverage` (so the planner, runs, missing characters and tallies), `Languages.coversWell` markers, suggestions, shaping alternatives and the real-weight superset check. `FaceRecord.groupCounts` is already plannable after WP-107, and when FPCore computes it itself it counts `plannableCoverage`. The raw `coverage` is used only for display and diagnostics, the glyph-share denominator (`GlyphBudget.faceGlyphShare`, as in the original) and the shaping rule below.
- `ScriptGroup.needsShaping` is the engine's `COMPLEX_GROUPS` = {`hebrew`, `arabic`, `indic`, `southeastAsian`} (WP-301 AC-301-17 checks it against `spec/fixtures/shaping/ot_alternatives.json`).
- **Shaping rule** (port of `shaping.rule_errors`, WP-107 §5): for each group `g` with `g.needsShaping`, in `ScriptGroup` order, let `r = scriptRules()[g]`. It is a problem when `r` is a valid index, material `r` is available, `face_r.coverage` (raw) has at least one code point of `g`, and `face_r.shapesGroups` is non-nil and does not contain `g`. A rule to a face that shapes part of `g` is not a problem; the unshaped characters simply go to other fonts. Because automatic rules come from plannable counts, in practice only a user pin triggers it.
- A record without `unshaped` decodes it as empty, and a record without `shapes_groups` decodes it as nil ("unknown": never blocks). Both keep pre-WP-107 data and hand-written test faces working.

### Design

#### 1. `FaceKey`

```swift
public struct FaceKey: Hashable, Comparable, Codable, Sendable, CustomStringConvertible {
    public var path: String   // absolute, standardised by the discovering component; never rewritten here
    public var index: Int     // TTC/OTC face index, 0 for single fonts
    public init(path: String, index: Int)
    // Comparable: by path (String <), then index. description: "\(path)#\(index)"
}
```

Paths are compared as exact strings. No Unicode normalisation (`ENGINE-8` verifier: "skip the NFD normalisation unless a mismatch is shown").

#### 2. `CodepointSet`

```swift
public struct CodepointSet: Hashable, Codable, Sendable {
    public private(set) var ranges: [ClosedRange<UInt32>]    // sorted, non-overlapping, non-adjacent
    public static let empty: CodepointSet
    public init()
    public init<S: Sequence>(_ codepoints: S) where S.Element == UInt32
    public init(ranges: [ClosedRange<UInt32>])              // sorts and merges overlapping/adjacent input
    public init(scalarsOf text: String)                       // every Unicode scalar of the text
    public var count: Int                                     // Σ (hi - lo + 1), cached at init
    public var isEmpty: Bool
    public func contains(_ cp: UInt32) -> Bool                // binary search, O(log ranges)
    public func contains(_ scalar: Unicode.Scalar) -> Bool
    public func isSuperset(of other: CodepointSet) -> Bool    // linear merge
    public func intersection(_ other: CodepointSet) -> CodepointSet
    public func intersectionCount(_ other: CodepointSet) -> Int
    public func union(_ other: CodepointSet) -> CodepointSet
    public func subtracting(_ other: CodepointSet) -> CodepointSet
    public var codepoints: [UInt32]                           // expanded, ascending (tests and small sets only)
}
```

- JSON: `[[lo, hi], …]` exactly as `catalog/cache.py:13-20` (`_ranges`). Decoding sorts and merges, and throws `DecodingError.dataCorrupted` when an entry is not two integers, when `lo > hi`, or when `hi > 0x10FFFF`. Encoding writes the merged ranges.
- Never materialise a `Set<UInt32>` for font coverage. A 900-face catalog of CJK fonts would cost tens of MB. Every algorithm here works on ranges.

#### 3. `FaceRecord`

```swift

```

`plannableCoverage` is a stored property so that suggestions over a 1,000-face catalog do not subtract sets on every call. Because `unshaped` and `coverage` are `var`s, implement them with `didSet` (or make them `private(set)` with a `mutating func setCoverage(_:unshaped:)`) so the stored value can never go stale. The memberwise init and the decoder compute it once; when `unshaped` is empty it is `coverage` itself.

#### 5. `ScriptGroup` and the generated table

```swift
public enum ScriptGroup: String, CaseIterable, Codable, CodingKeyRepresentable, Sendable, Comparable {
    case latin, greek, cyrillic, armenianGeorgian = "armenian_georgian", hebrew, arabic, indic,

    public static func of(_ cp: UInt32) -> ScriptGroup      // binary search in ScriptGroupTable; > 0x10FFFF → .other
    public static func of(_ scalar: Unicode.Scalar) -> ScriptGroup
    public static func groupsCovered(_ set: CodepointSet) -> [ScriptGroup]   // scripts.py:65-68, in allCases order
    public static func codepoints(of group: ScriptGroup) -> CodepointSet    // every code point of the group, from the
                                                                             // table; built once (static let dictionary)
    public static func counts(in set: CodepointSet) -> [ScriptGroup: Int]    // set ∩ codepoints(of:) per group, zeros omitted
    public var needsShaping: Bool   // ADR-0008 / engine COMPLEX_GROUPS: hebrew, arabic, indic, southeastAsian

```

`allCases` order is `GROUPS` (`engine/scripts.py:16-32`) and `Comparable` follows it. Raw-value enums get no synthesised `Comparable`, so implement `<` with a precomputed declaration-order index. `CodingKeyRepresentable` (default implementation for `String` raw values) makes `[ScriptGroup: X]` encode as a JSON object.

Swift has no Unicode Script property, so `group_of` cannot be re-implemented. The table is generated from the fixture by WP-202 (helper.md WP-202 §8; `tools/conformance/swift_tables.py`, run by `generate.py` inside `make conformance`, and covered by `make conformance-check`). WP-301 consumes it and does not write a generator:
  ```swift

  enum ScriptGroupTable {
      static let starts: [UInt32] = [0x000000, 0x000041, …]        // one per range, 8 per line
      static let groups: [UInt8] = [14, 0, …]                       // parallel array: index into GROUPS order (0 = latin … 14 = other)
  }
  ```
- `ScriptGroup.of(cp)` returns `ScriptGroup.allCases[Int(groups[i])]` for the last `i` with `starts[i] <= cp`. Build that mapping once (for example a `static let` array of `ScriptGroup` parallel to `starts`); do not map on every lookup.

`needsShaping` is the ADR-0008 list and equals `COMPLEX_GROUPS` in `engine-metadata.md` S4 (Hebrew included: the engine decides per face, via `unshaped`/`shapes_groups`, whether plain Hebrew letters are fine). `groupsCovered`, `counts(in:)` and `Plan.tallies()` intersect ranges with `codepoints(of:)`; none of them iterates code points.

#### 6. `TextUtil`

```swift
public enum TextUtil {
    public static let ignorableRanges: [ClosedRange<UInt32>]   // textutil.py:7-8, verbatim
    public static func isIgnorable(_ scalar: Unicode.Scalar) -> Bool
    public static func visibleScalars(in text: String) -> [Unicode.Scalar]   // sorted by value, unique
}
```

`isIgnorable(s)` = `s.properties.isWhitespace` || `s.value` in `ignorableRanges` || `s.properties.generalCategory` ∈ {`.format`, `.control`, `.unassigned`}. This mirrors `textutil.py:11-18`. Python's `str.isspace()` differs from the Unicode `White_Space` property only on U+001C…U+001F, which are `Cc` and therefore ignorable either way.

**Unicode version policy.** Python 3.12's `unicodedata` is Unicode 15.0. Swift's stdlib tables follow the toolchain (15.0 or newer for Swift 6.1/6.2 on Linux; 17.0 for the Swift 6.4 toolchain of Xcode 27 on the audit Mac, where U+1F600 reports age 6.1 and U+2FFFF none). Code points assigned after 15.0 are `Cn` (ignorable) in Python and visible in Swift. **FPCore uses the Swift tables at runtime.** A character the running macOS knows is a real character, and if no material draws it, listing it as missing is the honest answer. Conformance therefore compares only code points whose Swift `properties.age` is non-nil and ≤ the fixture's `unicode_version`. On the audit Mac (Swift 6.4, Unicode 17) that rule explains all 10,615 differences and leaves 0 unexplained. A mismatch on an older code point fails the test. It may be allow-listed only in the test file, one code point per entry, each with a comment naming the Unicode change. The list is expected to stay empty.

```swift
    /// planner.py:10-16. The rule's material when it has the code point; else the first material that has it; else nil.
    /// A rule index outside 0..<coverages.count is ignored.
    public static func sourceOf(_ cp: UInt32, coverages: [CodepointSet], rules: [ScriptGroup: Int]) -> Int?
    /// planner.py:19-27, computed by an interval sweep (below). Same result as calling sourceOf for every code point.
    public static func plan(coverages: [CodepointSet], rules: [ScriptGroup: Int]) -> Plan
}
public struct Plan: Sendable, Equatable {
    public static let empty: Plan
    public let assignments: [CodepointSet]           // per material index; pairwise disjoint; union = union of coverages
    public init(assignments: [CodepointSet])         // for tests (Appendix A row S21) and callers that build a plan by hand
    public var totalCodepoints: Int { get }
    public func source(of cp: UInt32) -> Int?        // binary search over assignments
    public func tallies() -> [[ScriptGroup: Int]]    // per material: code points per group, zero groups omitted (model.py:87-95)
}
```

**Sweep algorithm (normative result, suggested implementation).**

1. Boundaries = {`lo`, `hi + 1`} of every range of every coverage, plus every `ScriptGroupTable.starts` value strictly between the smallest and largest boundary. Sort and de-duplicate.
2. Keep one cursor per coverage. For each elementary interval `[b[k], b[k+1] - 1]`: advance each cursor past ranges that end before `b[k]`. Material `i` covers the interval when its current range starts at or before `b[k]`. Within an interval both the covering set and the group are constant.
3. Skip the interval if no material covers it. Otherwise `g = ScriptGroup.of(b[k])`, and `src = rules[g]` if that index is in range and covers the interval, else the first covering index. Append the interval to `assignments[src]`, merging with the previous range when adjacent.

The cost is O((total ranges + 824) × materials). A Python transcription of this algorithm matched the reference `plan()` on 300 seeded random cases during spec writing. Non-normative Python reference:

```python
# covs: list of sorted merged [lo, hi] lists; starts/groups: the group table
bounds = sorted({lo for rs in covs for lo, _ in rs} | {hi + 1 for rs in covs for _, hi in rs}
                | {s for s in starts if lo_all < s < hi_all})
for a, b in zip(bounds, bounds[1:]):
    cov = [covers(i, a) for i in range(n)]          # advancing cursors
    if not any(cov): continue
    g = group_at(a); r = rules.get(g)
    src = r if r is not None and 0 <= r < n and cov[r] else cov.index(True)
    append(out[src], a, b - 1)
```

`Mix` caches the effective coverages in a stored property at `init`. `==` compares `fonts`, `rules` and `baseIndex` only.

`MixRun.source` for a scalar that a face covers but cannot shape (`unshaped`) is the next font that has it in its plannable coverage, or nil. The preview (WP-504) then draws exactly what the forged font maps, because the engine plans with the same plannable sets (`engine-metadata.md` WP-107 §4).

**Runs.** Walk `text.unicodeScalars`. For each scalar compute `s = source(of:)`. A scalar that is `TextUtil.isIgnorable` and has `s == nil` joins the current run, or starts a `nil` run when it is first. Any other scalar starts a new run when `s` differs from the current run's source. Runs are maximal, cover the text without gaps, and the `utf16Range`s are consecutive: a non-BMP scalar adds 2 to the UTF-16 offset. The empty text gives `[]`. The ignorable rule keeps joiners, variation selectors and line breaks from splitting a run into LastResort boxes. The preview still draws exactly what the forged font maps. The missing list never includes ignorable scalars (`test_model.py:271-279`).

- `.cannotShape(i, g)`: the S7 shaping rule, one per complex group in `ScriptGroup` order, `i` = the rule's material. That rule points `g` at a face that would lose its shaping in the forged font (`ENGINE-2`, ADR-0008); the engine refuses the same spec with `aat_unsupported_script` (contracts §5).
- `.glyphLimit` when `glyphEstimate > 65_535`.

#### 6. `reconcile(with:)`: port of `set_catalog` without silent drops

```swift
public struct ReconcileReport: Sendable, Equatable {
    public struct Relocation: Sendable, Equatable { public let index: Int; public let from: FaceKey; public let to: FaceKey; public let resolution: FaceResolution }
    public var refreshed: [Int] = []     // same key, record changed (rescan found a new size/mtime/metadata)
    public var relocated: [Relocation] = []
    public var nowMissing: [Int] = []
    public var recovered: [Int] = []     // were unavailable, available again
    public var changed: Bool { get }
}
```

For each material `i` in order:
1. The catalog has `m.key` with the same PostScript name, or either name is nil. Store the catalog record if it differs (`refreshed`). If the material was unavailable, mark it available (`recovered`).
2. Otherwise `catalog.resolve(m.face.identity)` excluding `.byPath`. If it finds a face whose key is not another material's key, relocate: the key changes everywhere (pins, base), weight and scale are kept, and the material becomes available (`relocated`, and `recovered` too if it was unavailable). Otherwise mark it `.fileGone` if it was available (`nowMissing`), and keep `.notFound`/`.fileGone` as they are.

When anything changed, refresh names. The original dropped vanished materials together with their pins (`model.py:444-450`). The Swift port keeps them, visible and flagged (architecture §8, `ENGINE-8`, `CATALOG-7`). The user replaces or removes them. `AppModel` calls `reconcile` after every catalog refresh (WP-501).

#### 7. Staleness (guidance for WP-505; nothing to implement here)

The original bumps a serial on every edit that changes what gets drawn (`model.py:745-750, 797-816`). The Swift equivalent is value equality: a built result is stale exactly when `recipe.forgeSpec() != specUsedForTheBuild`. `sampleText`, `suggestedFileName` and a `setFamily` with the same text do not change the spec. Adjustments, order, rules, names and rescanned files (`expect`) do. AC-303-9 locks these semantics.

### Notes for the implementer
- Port `test_model.py` first (Appendix A), then implement until it is green. The original tests are the spec (plan §7 risk 1).
- Keep state-mutating operations in `Recipe.swift`: Swift restricts `private(set)` setters to the declaring file, so cross-file operation extensions cannot preserve the required public API. Derived operations remain in extensions; `ReconcileReport` has its own file.
- Pins are keyed by `FaceKey`, so every key change (`replace`, relocation in `reconcile`) must rewrite `pins` and `baseKey` in the same mutation.
- Names are refreshed only by operations that change materials or their order (`_materials_edited`, `model.py:734-738`), not by `setPin`, `setAdjustments`, `setBase` or `setDefaults`.
- `familyNameStartsWithDot` exists so WP-505 can close `UI-M3` without a second validity path. WP-505 owns the UI.
- Missing materials keep their `FaceRecord`. The planner treats them as empty, so they draw nothing. Auto names still include their family, so "Georgia SimSun" survives a missing SimSun.
- `RuleResolver.counts` returning 0 for `suspiciousCoverage` faces is defensive: WP-401 already drops `.LastResort` as hidden (`CATALOG-2`, ADR-0007).
- `.cannotShape` mirrors the engine's rule check (`engine-metadata.md` WP-107 §5), which looks at **rules**, not at the plan. With plannable coverage a face's tally never contains characters it cannot shape, so a tally-based check would never fire. Keep the two in step: if WP-107's rule changes, change S7 and AC-303-14 in the same PR.

```swift

    public func glyphsNeeded() -> Int      // model.py:524-533: main.glyphCount + Σ_{i>0} faceGlyphShare(face_i, plan.assignments[i].count); 0 when empty
    public func suggestions(in catalog: FaceCatalog, limit: Int = 3, preferences: PlatformPreferences = .macOS) -> [FaceRecord]
    public func suggestions(for language: LanguageID, in catalog: FaceCatalog, limit: Int = 3,
                            preferences: PlatformPreferences = .macOS) -> [FaceRecord]
```

`suggestMaterials` is `smart.py:157-193` with the macOS filters:

1. Return `[]` when `missing` is empty or `limit <= 0`.
2. Skip a candidate when `!supported`, `hidden`, `suspiciousCoverage`, or its key is in `excluding` (`CATALOG-2`).
3. `covered(face)` = `missing.intersectionCount(face.plannableCoverage)` (S7: a character the face cannot shape does not count, ADR-0008). Skip the face when `covered == 0`. Skipped faces take no part in step 4.
4. Pick one face per family (exact family string). Rank inside a family by `(italic == wantItalic ? 0 : 1, |weightClass − wantWeight|, catalog position)`, where `want*` comes from `main` (400/upright without one). Families are listed in order of first appearance.
5. Sort families stably by `(exceedsGlyphBudget(face, mainGlyphs), −covered(face), PlatformPreferences.rank(of: face, in: preferred), face.glyphCount)`, using each family's chosen face. Take `limit`. With `preferred == []` every rank is `Int.max`, which reproduces the original order exactly.

`Recipe.suggestions(in:)`: `missing = CodepointSet(missingSampleCharacters())`, `candidates = catalog.faces`, `main = self.main`, `excluding = Set(keys)`, `mainGlyphs = glyphsNeeded()`, `preferred = preferences.entries(for: Languages.languagesForMissing(missingSampleCharacters()).map(\.id))`. An empty catalog gives `[]`.

`Recipe.suggestions(for:in:)`: same, but candidates are restricted to faces with `Languages.coversWell(face, language)` (plannable counts and markers, S7, so an AAT-only face never "draws Arabic well"), and `preferred = preferences.entries(for: [language])`. `.any` keeps every face (`model.py:503-512`).

#### 3. Nearest real weight (ENGINE-4)

The engine emboldens when `weight − weightClass ≥ 50` for a face without a `wght` axis, and cannot lighten (`engine/prepare.py:165-171`, `synth_bold.py:8` caps the delta at 500). Synthetic bold on PingFang takes 25–32 s, doubles the output (10.9 → 24 MB) and failed on 2 of 36,717 glyphs at +300, while the real Semibold at +100 had 0 failures (`ENGINE-4` verifier). Apple ships real weights: PingFang SC Ultralight/Thin/Light/Regular/Medium/Semibold (100–600), Hiragino Sans W0–W9 (100–900), Apple SD Gothic Neo (100–900). Some heavier faces cover fewer characters: on the audit Mac Hiragino Sans W7–W9 have 8,347 code points against 13,861 for W3, Songti SC Black 8,159 against 32,965, and Avenir Next Heavy 378 against 976. **A swap must never lose a character the material draws.**

```swift
public struct WeightSwap: Sendable, Equatable {
    public let index: Int
    public let from: FaceRecord
    public let to: FaceRecord
    public let requestedWeight: Int
    public let remainingSyntheticBold: Int    // 0 when to.hasWeightAxis or requestedWeight − to.weightClass < 50,
                                              // else min(requestedWeight − to.weightClass, 500)
}
public enum WeightNote: Sendable, Equatable {
    case syntheticBold(index: Int, delta: Int)   // delta = min(W − weightClass, 500), W − weightClass ≥ 50, no wght axis
    case cannotMakeLighter(index: Int)           // W − weightClass ≤ −50, no wght axis
}
extension Smart {
    public static func nearestRealWeight(for face: FaceRecord, requested weight: Int, mustCover drawn: CodepointSet,
                                         in catalog: FaceCatalog, excluding: Set<FaceKey>) -> FaceRecord?
}
extension Recipe {
    public mutating func applyRealWeights(in catalog: FaceCatalog) -> [WeightSwap]
    public func weightNotes() -> [WeightNote]
}
```

**Rule.** For an available material `i` (the main font included: its resolved weight is the default weight) with face `F` and resolved weight `W = weight ?? defaultWeight`:

1. Do nothing when `W == nil`, when `F.hasWeightAxis` (the engine instances it), or when `|W − F.weightClass| < 50`.
2. Candidates `G` in `catalog.faces(family: F.family)`: `G.key != F.key`, `G.italic == F.italic`, `G.supported`, `!G.hidden`, `!G.suspiciousCoverage`, `G.key ∉ excluding` (the other materials), and `G.plannableCoverage.isSuperset(of: drawn)` (S7), where `drawn` is material `i`'s assignment in the current plan. A material that draws nothing is never swapped.
3. Choose `G` minimising `|W − G.weightClass|`. On a tie, prefer `G.weightClass ≥ W` (no synthetic bold needed), then catalog order. A candidate with a `wght` axis whose range contains `W` has distance 0.
4. Swap only when `|W − G.weightClass| < |W − F.weightClass|` (distances as in step 3).

`weightNotes()` lists, for every available material with a resolved `W` and no `wght` axis, `.syntheticBold(i, min(W − wc, 500))` when `W − wc ≥ 50` and `.cannotMakeLighter(i)` when `W − wc ≤ −50` (`engine/prepare.py:165-170`), in material order.

`applyRealWeights` computes the plan once, visits materials in order, and applies each swap like `replace(key, with: G, keepAdjustments: true)`: pins and base follow, the requested weight stays, and names refresh (a swapped main can change the proposed style). A face whose `weightClass` misreports its weight (Kaiti SC Bold reports 400 on the audit Mac) is never chosen for 700, because it is not nearer. That is acceptable.

**How it is surfaced.** The default is to prefer real faces. `AppModel` calls `applyRealWeights(in:)` right after every user action that changes a resolved weight: a Weight choice on a card, Default boldness in Advanced, and `add`/`replace` while a default weight is set. It shows each returned swap as a one-line note on the card with Undo, which restores the previous `Recipe` value. WP-502 and WP-506 own that UI. `weightNotes()` lists what the engine will still do synthetically, so the card can say so before building.

`EnglishText`: `weightSwap(_:)` = `Using \(to.displayName) instead of making \(from.displayName) bolder.` (or `lighter` when `requestedWeight < from.weightClass`); `weightNote(.syntheticBold(i, d))` = `Made bolder synthetically (+\(d))`; `weightNote(.cannotMakeLighter(i))` = `Can't be made lighter; weight left as is`.

#### 5. Naming: conformance, macOS refinement and the PostScript name

- `NamingConformanceTests` compare `Naming` with every case of `spec/fixtures/naming/family-names.json`. Cases whose input family (or any family in the list) starts with `"."` are skipped, and the test prints how many it skipped. Those inputs follow the macOS rule below instead.
- macOS refinement (`ENGINE-10` verifier, `UI-M3`): `defaultFamilyName` removes leading `"."` characters from each family after `stripVendor`, and ignores a family that becomes empty. `fileName` removes leading `"."` characters from the stem and then leading whitespace (the `cleanName` set). An empty stem becomes `Forged-Regular`. This is exactly mac-services.md WP-403 §7 step 3 (`InstallFileName.stem`), and ui-shell.md AC-505-31 checks that the two agree. Hidden faces are already dropped by WP-401, so this is defensive. The engine rejects a family that starts with a dot (WP-109 §5), and the proposals never do.
- **PostScript name** (contracts §6; the algorithm is normative in `engine-metadata.md` WP-109 §2, and the Swift port must match it byte for byte). WP-403/WP-505 use it to check the name a build will get before building or installing.

```swift
extension Naming {
    public static func fnv1a64(_ bytes: [UInt8]) -> UInt64                     // offset 0xcbf29ce484222325, prime 0x100000001b3, wrapping
    public static func asciiAlnum(_ s: String) -> String                        // keep only scalars in [A-Za-z0-9]
    public static func nameTag(family: String, style: String) -> String        // "FP" + 8 lowercase hex digits
    public static func postscriptName(family: String, style: String) -> String
}
```

`postscriptName`: `f = cleanName(family)`, `s = cleanName(style)`; `h = fnv1a64(Array(f.utf8) + [0] + Array(s.utf8))`; `tag = "FP" + String(format: "%08x", UInt32(truncatingIfNeeded: (h >> 32) ^ (h & 0xFFFF_FFFF)))`; `sty` = the first 20 characters of `asciiAlnum(s)`, or of `"Regular"` when that is empty; `fam` = the first `63 − 1 − sty.count − tag.count` characters of `asciiAlnum(f)`, or of `"Forged"` when that is empty; result `fam + tag + "-" + sty`. No Unicode normalisation (NFC and NFD spellings give different names, as in the engine).

#### 1. `RecipeDocument` v1

```swift

    public var materials: [DocumentMaterial]
    public var main: Int                     // the line-spacing (base) material; 0 = follows the first material
    public var rules: [ScriptGroup: Int]     // the user's pins as material indexes (not the automatic rules)

```

Mapping (contracts §8; a Python "main" is `base_index`, `model.py:695`):

| JSON | From `Recipe` | To `Recipe` |
|---|---|---|
| `format`, `version` | `"fontrecipe"`, `1` | `format` absent or different → `.notARecipe`. `version` not an int → `.notARecipe`. `> 1` → `.newerVersion(v)`. `< 1` → `.notARecipe` |
| `materials[].face` | `material.face.identity` (placeholders keep their identity) | resolved, see below |
| `materials[].weight/scale` | raw values, explicit `null` | kept as is (out-of-range values show up as problems) |
| `main` | `baseKey == nil ? 0 : index(of: baseKey)` | `i > 0` and in range → `baseKey = materials[i].key`; out of range → 0, reported |
| `rules` | `pins` → `{group id: index}` | unknown group id or index out of range → ignored, reported |
| `defaults` | `{weight, scale}` explicit null | absent → `{null, 1.0}` |
| `names` | family, style, flags | an unedited name is replaced by the proposal (`model.py:715-721`) |
| `sample_text` | as is | absent or empty → default; equal to `Samples.oldDefaultSample` → `Samples.defaultSample` (`model.py:725-727`) |

A missing optional key takes the default. Unknown rule names are retained internally until `makeRecipe` reports them; other unknown keys are ignored. A key present with the wrong JSON type throws `.malformed(field:)` with the JSON path (for example `"materials[2].weight"`). Invalid JSON throws `.unreadable`.

**Resolution** (`makeRecipe`). For each document material in order, run `catalog.resolve(identity)`:
- found, and the key is not already used → available material (`LoadReport.Outcome.byPath / .byPostScriptName / .byFamilyAndStyle`);
- found, but the key is already used → the material is dropped and reported as `.duplicate(of: earlierIndex)` (the earlier stored position); indexes in `main` and `rules` are remapped;
- `.unresolved` → **placeholder material** with `availability = .notFound` and `FaceRecord.placeholder(identity)`. Reported as `.notFound(replacements:)` with `WindowsFonts.replacements(forFamily: identity.family, in: catalog, main:)` (§5), where `main` is the first resolved material's face (nil when none resolved yet).

6. accepted. `insideApplicationBundle` is true when a path component ends in `.app`, so the UI can show a licence note before a scan of Office's `DFonts` (CRIT-3 point 3).

`WP-501` stores `AppSettings` in `UserDefaults` and owns the keys. It may add window-related values to its own type.

The functions never throw and never modify the legacy files. `WP-501` decides when to call them: at first launch when `last.fontrecipe` does not exist, `legacyImportDone` is false, and the legacy folder exists. It then sets `legacyImportDone = true` whatever the outcome, so the import is one-time.

**Tolerant parsing.** Parse with `JSONValue` (`null | bool | integer(Int) | number(Double) | string | array | object`, decoded in that order with `JSONDecoder`). The helpers port `model.py:106-139`:
- `asInt`: `.integer` → value; `.string` → `Int(Naming.cleanName(s))`; else nil (`bool` → nil). Deviation: `JSONDecoder` may read `700.0` as the integer 700 (it does on the macOS 27 SDK toolchain), which Python rejects. That is harmless.
- `asFloat`: `.integer`/`.number` → value; `.string` → `Double(Naming.cleanName(s))`; nil unless finite (`bool` → nil).
- `asKey`: an array `[string, asInt]` of length 2 → `FaceKey`.

**Recipe import** (port of `_clean_spec_dict` + `from_settings`, `model.py:142-170, 686-731`):
1. The top-level value is not an object → empty `Recipe()`, `readable = false`.
2. `materials`: a missing key or `null` counts as `[]`. Any other non-array also counts as `[]`, but adds one `.malformed` outcome, so a damaged or hand-edited file is not imported as a clean empty recipe (no silent drops; `wrongShapedMaterialsAreReportedNotImportedAsEmpty`). For each entry at original position `p`: not an object, or `asKey((path, index))` is nil → `.malformed` (dropped; later indexes are remapped exactly as `from_dict` remaps, `spec.py:84-95`). Otherwise resolve the legacy key:
   1. `catalog.face(for: key)` → `.byPath` (a file written by the Qt app on a Mac);
   2. the path looks like Windows (`FolderCheck` rule 2): the basename is the text after the last `\` or `/`, `WindowsFonts.faceName(forFile: basename, index: key.index)` gives family and style, and `catalog.face(family:style:)` → `.byWindowsFileName`;
   3. a catalog face whose path basename equals the legacy basename case-insensitively, with the same index → `.byFileName` (first in catalog order; this also recovers an AssetsV2 path whose hash folder changed, `CATALOG-7`);
   4. otherwise a placeholder (`.notFound`) with identity `(postscriptName nil, family and style from the file table, or the basename without extension and "Regular", the legacy path, index)` and CRIT-3 replacements.
   Duplicates → `.duplicate(of:)`. `weight = asInt`, `scale = asFloat`.
3. `base_index`: `asInt ?? 0`, counted in original positions and remapped. An index pointing at a dropped entry → 0.
4. `pins`: when the key `"pins"` exists and is an object, each `group: asKey(value)` whose group id is known and whose legacy key maps to a kept material is pinned to that material's **new** key. When `"pins"` is absent, every non-null `script_rules[g]` (remapped) becomes a pin (`model.py:704-707`).
5. `default_weight = asInt`, `default_scale = asFloat ?? 1.0`.
6. Names: `family_name`/`style_name` count only when they are strings. With `names_edited` an object, a flag is `bool(value)`. Otherwise the old-file heuristic applies: edited = the stored value exists and differs from the proposal computed from the imported materials, placeholders included (`model.py:708-721`).
7. `output_path`: only when `names_edited` is an object with `output == true` and the value is a string: `FolderCheck` on its parent folder (everything before the last `/` or `\`, or the whole value when it has neither). Accepted → `lastSaveDirectory`. Rejected → `ignoredOutputPath` (CRIT-2: the Windows path never pre-fills the Save panel).
8. `sample_text`: a non-empty string, with the old default → new default rule.

**Settings import** (port of `ui/app.py:60-72, 99-101, 300`): start from `AppSettings()`. Not JSON or not an object → defaults, `readable = false`. Then, for the four known keys only (other keys, such as a Windows window geometry, are ignored without a report):
- `theme`: one of `"system"`, `"light"`, `"dark"` → `appearance`; any other value → `ignoredKeys += ["theme"]`.
- `preview_size`: an `.integer` in 10…96 → `previewPointSize`; anything else (a bool, a fractional number, out of range) → `"preview_size"`. Integral JSON numbers such as `48.0` follow `JSONValue` decoding: accepted if the decoder represents them as `.integer`, otherwise reported.
- `colour_by_font`: `.bool(b)` → `colourByFont = b` (the original only honours `true`, so `false` and absent both give false); any other type → `"colour_by_font"`.
- `extra_dirs`: an array; each string through `FolderCheck`; accepted ones de-duplicated by standardised path in order, rejected ones in `droppedFolders` (in stored order). A non-string element → `ignoredKeys += ["extra_dirs[\(i)]"]`. Not an array → `"extra_dirs"`.

`ignoredKeys` is sorted. `legacyImportDone` stays false (WP-501 sets it).

### Notes for the implementer
- Placeholders are the no-silent-drop mechanism (architecture §8). Never "clean up" a recipe by removing `.notFound` materials in FPCore. Only the user removes them.
- `rules` in the document are the user's pins, not `Recipe.scriptRules()`. The automatic rules are recomputed on load. Writing them would freeze today's choice.
- Do not write personal paths into tests or fixtures. Use `/Users/Someone/…` and `C:\Users\Someone\…`.
- The legacy import runs against the Mac catalog after the first scan finishes (WP-501 waits for it). Calling it with an empty catalog would turn every material into a placeholder. That is correct, but useless to the user.
- `JSONDecoder` handles the top-level fragments `null`, `"text"` and `[]` (checked on the macOS 27 SDK toolchain). They must give `readable == false` and an empty recipe, not an exception.
